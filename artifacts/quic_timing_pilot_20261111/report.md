# QUIC22 包间隔融合小实验

## 数据和比较口径

来源为 [CESNET-QUIC22 官方归档](https://zenodo.org/records/10728760)。对 27 个归档日各读取 ZIP 中当天流量成员开头的 4 MiB，合计解析 834,241 条完整记录。片段覆盖各日同一钟点附近的约 14 至 29 分钟。按归档日用 2022-10-31 至 11-06 拟合，跳过 11-07，11-08 至 11-27 留出。首尾时间验证了拟合和留出流区间不重叠。原始片段的字节范围及 SHA-256 见 `summary.json`。

只保留至少五个有效 PPI 包且整个流落在同一个记录小时的流。排除背景标签，按拟合样本量选八个服务，采用均匀类别先验。拟合 99,298 条、留出 283,526 条。粗表示为 EIBO 的前五包方向及 `log M=2` 包长。细表示保留粗符号，并增加第二包间隔分箱，右闭边界为 0、1、4、16 毫秒。两组用完全相同的流和类权重。冻结的融合规则是拟合期加权频数分类器，未见细符号回退到粗规则。

## 结果

| 留出归档日 | 流数 | 粗表示样本上限 | 加间隔样本上限 | 样本增益 | 逐流独立假设下的 95% 增益下界 |
|---|---:|---:|---:|---:|---:|
| 11-08 至 11-27 | 283,526 | 50.59% | 56.03% | +5.44 pp | +4.81 pp |
| 11-08 至 11-17 | 141,682 | 50.47% | 56.07% | +5.59 pp | +4.60 pp |
| 11-18 至 11-27 | 141,844 | 50.75% | 56.02% | +5.27 pp | +4.57 pp |

样本上限由每个符号在留出集上选择类别先验加权频数最高的标签计算，等价于该表示在当前经验分布的贝叶斯准确率。这里复现的是 [Huang 与 Yang 表 11](https://arxiv.org/html/2609.02140v1) 的匹配比较思路。类别、采样范围和编码与原文不同，数值不能直接对比。

### 有限样本下界

总体目标为细表示和粗表示各自最优的平衡准确率之差。全期冻结融合规则的留出准确率为 55.86%，减去粗表示样本上限后得 5.27 pp。这个样本差值至多等于该融合规则对总体最优粗规则的样本差值。给定拟合结果和各块类计数，假设不同块独立且目标为对应的类加权流量混合分布。各块配对得分位于 `[-w_b, w_b]`，其中 `w_b` 是该块的总样本权重。Hoeffding 半径为 `sqrt(2 * log(1/alpha) * sum(w_b**2))`，把半径从样本差值扣除，再利用真实增益非负截断到零。块内允许任意相关。

| 块长 | 非空块数 | 半径 | 95% 下界 |
|---|---:|---:|---:|
| 1 小时 | 40 | 49.47 pp | 0 pp |
| 6 小时 | 20 | 54.75 pp | 0 pp |
| 24 小时 | 20 | 54.75 pp | 0 pp |
| 48 小时 | 11 | 75.45 pp | 0 pp |

两个十日子期在同样的块长下也全部为零。块独立是敏感性分析的假设，时间分块本身无法验证它。当前片段集中在相近时段，1 小时分组的有效块数仅 24.48。这个有限样本方法没有给出正下界。

### 逐日敏感性

冻结融合规则在 20 天都超过当天的粗表示样本上限，最小差值 3.89 pp，逐日等权均值 5.11 pp。对这 20 个逐日差值做 20,000 次循环移动块重采样，块长 1、2、4 天所得均值的 5% 分位数分别为 +4.91、+4.89、+4.90 pp。该分析等权平均每天，依赖日序列近似平稳且相关性随时间衰减。20 天不足以确认这些条件或支持可靠的有限样本覆盖。它提供了收益分布在多日的证据。

## 复跑

在仓库根目录，使用 `summary.json` 列出的官方 URL、归档大小和 `files` 字段中的字节区间恢复 `<date>.prefix`，用 SHA-256 核验。`quic22-tail.bin` 对应归档的 `20951942720-20952008297` 字节，用于读取 ZIP 目录。依赖现有 NumPy、SciPy 环境。

```bash
python3 scripts/quic_timing_pilot.py \
  --prefix-dir data/quic_timing_pilot \
  --out data/quic_timing_pilot/recheck.json
```

## 学校服务器上的 QUICEXT-25 XS

使用服务器已有的 `traffic-ncde` 环境与 PyTables。H5 模式使用全年数据的日历 50/25/25 切分，两个留出期开始前各留一天间隔。拟合期按可用流数固定选取 8 个 APP 编码，使用均匀先验。它沿用上面的表示与增益界，语料、类别和日期与 QUIC22 小实验不同。

```bash
cd /data/xjw/EIBO
git switch codex/methodology-risk-certificates
git pull --ff-only origin codex/methodology-risk-certificates
python -u scripts/quic_timing_pilot_h5.py \
  --h5 /data/xjw/CESNET-QUICEXT-25/XS/CESNET-QUICEXT-25-XS.h5 \
  --backend tables \
  --expected-sha256 6b323c4c53b7c9d0ec9011f895b3c5ba6b35247576e41ef19fe84ab8632810ab \
  --out "artifacts/methodology/quic_timing_xs_$(date +%Y%m%d_%H%M%S).json"
```

输出 `results.certificate`、`results.evaluation` 和合并后的 `results.all`。各组提供 `coarse_ceiling`、`fused_ceiling`、`sample_ceiling_gain`、冻结分类器准确率和 `bounds`。`1h` 至 `48h` 按流开始时间分组，`span_merged_*` 额外合并可能被同一条流跨越的相邻时间块。合并采用 H5 整点截断的一小时结束时间包络。块内允许任意相关，各下界仍以相应块之间独立为条件。脚本按块读取 H5，只输出聚合结果。
